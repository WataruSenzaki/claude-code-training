## 1. Mainline（4段）

> 出口ゲート: **「起動済みの状態から、話しかけてファイルを1つ読ませ／直させ、承認して反映できる。詰まっても、止める・仕切り直す・閉じて開き直す、で自力復帰できる」**（二値・対象非依存）
> 触る面: CLI（ターミナル）固定。OS 分岐はほぼ無い（終了キー・`claude` は共通）。

| 段 | やること | 具体 | ねらい |
|---|---|---|---|
| 1. 話しかける | やってほしいことを日本語でそのまま打つ | 例「このフォルダに何があるか教えて」 | 命令の呪文は要らない＝身構えを外す |
| 2. ファイルを読ませる・直してもらう | ファイル名（パス）を渡して読ませ、直した結果を確認する | 例「`議事録.txt` を読んで要点を3つに」→「清書版を `議事録_清書.txt` に保存して」 | チャットAIとの最大の差＝手を動かしてくれる |
| 3. 承認する【安心の柱1】 | 変更の前に「これ変えていい？」が出る。許可するまで変わらない | 内容を見て 許可／やめて | 勝手に壊されない＝怖くない |
| 4. 詰まったら自分で戻る【安心の柱2】 | 止める・仕切り直す・閉じて開き直す | `Esc`＝止める／`/clear`＝仕切り直し／`Ctrl+C` 2回＝終了→`claude`＝再起動 | 一人で抜け出せる＝使い続けられる |

### 確定事実（裏取り済み）

- **Esc**＝応答・ツール実行を**途中で中断**（やった分は残る）。長い・的外れな生成を途中で切れる
- **Ctrl+C**＝操作中は中断。何も走っていなければ1回で入力消去・**2回で終了**。**Ctrl+D** でも終了
- **`/clear`**＝文脈をリセットして新しいセッションを開始。**前の会話は保存され、後で再開できる**
- 再開＝同じフォルダで **`claude -c`（`--continue`）** で直近の続きから。**`claude -r`** で名前・ID から選んで再開
- 承認＝既定では変更前に確認が出る。受講者の設定モード次第で出ないことがある（→確認状況に記載）

### 前提条件（Mainline ではない）

- セットアップ完了（`claude` が起動し、打てば応答が返る状態）。基本操作はそこから始まる

## 2. Add-on カタログ（目的タグ＋接続点）

> 目的タグは選別フィルタも兼ねる。「動機を強化するか／疑問を解消するか」のどちらでもない候補は、Add-on に入れない。
> 対象が変わったら、Mainline と Add-on の池はそのまま、構成で「どの Add-on を選ぶか」だけ変える。

| Add-on | 目的タグ | 接続点 |
|---|---|---|
| 見ている場所は基準点（パスを渡せばどこでも読む／無ければ探す。起動場所に縛られない） | 疑問解消 | 段1前 or 段2 |
| ただし CLAUDE.md（自分ルール）だけは起動場所を基準に読まれる → 詳しくは L2 | 疑問解消 | 段1前（上の続き） |
| 頼み方のコツ（具体的に・段階的に。対象・形・条件を足すほど近づく） | 動機強化＋疑問解消 | 段1後 |
| 直した結果はどこに保存されるか（出力ファイルの置き場を指定できる） | 疑問解消 | 段2後 |
| スラッシュコマンドとは（`/` で始まる命令メニュー。`/clear` がその一例） | 疑問解消 | 段4 |
| 同じ依頼の繰り返しが面倒 → ルール／スキルで自動化できる（L2 予告） | 動機強化 | 段4後 |

### フィルタで弾いたもの（mechanics でない／過剰＝Add-on に入れない）

- 仕事の具体例（文章整え・データ整理・フォルダ横断）→ L3（自社業務への応用）の素材であって、操作の習得ではない
- チャットAIとの差分・複数ファイル横断の凄さ → 導入（ユニット1）／L3 の動機パート。ここでは扱わない
- vim モード・履歴検索（Ctrl+R）など上級ショートカット → 非エンジニアには過剰

## 3. フラグ（非エンジニア向けで効く論点）

- **「見ている場所」を Mainline から外した理由**: パスを渡せばどこのファイルでも読み、無ければ探せる。起動場所は相対パスとデフォルト探索の**基準点でしかなく**、ファイル操作を縛らない。試作スライドの「机の上だけ・別の部屋は見えない」は言い過ぎなので採らない（場所を過剰に怖がらせ逆効果）。場所が本当に効くのは **CLAUDE.md の読込範囲**だけで、それは L2 の領域。だから L1 では一言の Add-on に留めた。
- **「自立トリオ」を Mainline に据えた理由**: 非エンジニアが初回ソロで詰まると「壊した気がして二度と触らない」で終わる。止める・仕切り直す・閉じて開き直す、を知っているかが「使えるようになった」の閾値。だから周辺 Add-on ではなく本体（Mainline 段4）に置いた。
- **安心の2本柱**: 承認（勝手に変えない）＋自立（いつでも止められる・やり直せる）。この2つで「怖くない」を締める。
