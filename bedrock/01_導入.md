# 導入（Unit）

> 本ファイル＝ L1 Bedrock の Unit「導入」。L1 の最初。手を動かさない動機＋理解パートで、次の [02_契約.md](./02_契約.md) → [03_セットアップ.md](./03_セットアップ.md) へつなぐ。
> 構成は確定スライド `slides/導入.html` と一致させてある（2章立て）。

## サマリ

- 結論: 導入は **2章**。章1「Claude Code とは」（作業の代行者 → チャットとの違い → 本来はコーディング用 → 仕組みはファイルの読み書き → 仕事道具として広がり）＋章2「本講義の役割」（この講座の目標 → そこまでの道のり → まず、動く環境をつくる）。手を動かさない動機＋理解パート。
- ゲート: **持たない**（動機・理解は二値で測れない。成立の目安＝次〔契約〕に進む気になっている）。
- 次のアクション: 「CC を動かすには、まず動く環境（契約から）を整える」と腹落ちしたら [02_契約.md](./02_契約.md) へ。実際に手を動かすのは [03_セットアップ.md](./03_セットアップ.md) から。

## 1. 何を伝えるか（Mainline・2章）

> 動機: **作らない**。受講者は既に「自分で楽になりたい」を持って来る。だから既にある関心に「CC とは何か → 完成品（行き先）→ まず動く環境（契約）」を接続するだけにし、焚きつけ型の煽り（『すごいだろ→だから始めよう』式）は使わない（動機を持つ受講者には効かない）。
> 出口ゲート: **置かない**。導入は手を動かさない動機＋理解パートで、到達を二値で測らない。成立の目安＝「『CC がどういう道具か』と『この研修がどこを目指すか』が腹落ちし、次（契約）に進む気になっている」。
> 触る面: なし（手を動かすのは 03 から）。触る面（CLI／デスクトップ）の違いは同一エンジンで成立するので Add-on。対象で変わるのは完成品の例・刺し方とスコープの線引き（やる／やらない）＝ Add-on（[add_on/00_index.md](./add_on/00_index.md)）。流れ自体は対象で変わらない。
> 用語・命名: 同じものを別名で呼ばない（一語一階層）。この層は「動く環境」と呼ぶ（裸の「環境」「土台」は使わない）。"最初・飛ばせない" の含みは名詞でなく「まず」で運ぶ。認証まわりは概念＝「認証」（傘）、操作＝「ログイン」（手段＝03 段3）と階層で分ける（公式も Authentication 下に OAuth ログイン／API キー／クラウド認証を並べる）。

### 章1「Claude Code とは」

> 一本の論で進む: **代行者（で）→ チャットとの違い（でも）→ 本来はコーディング用（ただ）→ 仕組みはファイルの読み書き（ゆえに）→ 仕事へ広がる（だから）**。正体を先に正直に置き、それを書類仕事へ橋渡しする順。「コーディングエージェント」を先頭に出すと非エンジニアは離れやすいので、正体（＝作業の代行者）を先に置き、出自（コーディング用）は3番目に回す。

| 節 | 伝えること | 核 | ねらい |
| --- | --- | --- | --- |
| 1. 作業の代行者 | 一言でいうと「頼んだ作業を、代わりにやる」。調べる・読む・書く・直す＝PC 上の作業を肩代わり。指示するだけで任せられる | 正体＝作業の代行者 | まず正体を正直に置く。"使われ方の断定" でなく "道具の正体" なので誇張なく言える |
| 2. チャットAIとの違い | チャットは聞けば答えるだけ。CC は頼めば代行する。例＝議事録を要点3つにまとめて保存／30個のファイル名を一括で直す／資料から数字を集めて1つの表に | 違い＝代行する（チャットは答えるだけ） | 代行の中身を具体例で掴ませる（売り込みでなく理解として） |
| 3. 本来はコーディング用 | 正体は "コーディングエージェント" ＝もとはエンジニアの開発の道具。エンジニアが手で書き換えていたファイルを、AI が代わりに直す | 出自＝エンジニアの開発の道具 | 出自を隠さず正直に置く（"汎用 AI" と薄めない） |
| 4. 仕組みはファイルの読み書き | コードも書類（Excel・Word・PDF）も結局 "PC の中のファイル"。CC がやるのはファイルを読み・書き換えること。だから代行はコードに限らない、書類の仕事でもできる | 仕組み＝ファイルの読み書き | 出自（コード）と書類仕事を橋渡しする。導入の肝 |
| 5. 仕事道具として広がりを見せている | これまで＝エンジニアの開発の道具／いま＝事務・資料・データの仕事へ。どんな仕事も中身はファイル操作だから、他の仕事にも広がってきている | 広がり＝事務・資料の仕事へ | エンジニアの道具を自分事に接続する |

### 章2「本講義の役割」

> 完成品（行き先）を見せ → 道のりを渡し → 「動かすにはまず動く環境が要る」で次章（契約）へ橋渡しする。報酬は L2・L3 側（貯まる／自社業務）にあり L1 はそこへ至る前提なので、行き先を先に見せて L1 を通る動機にする。完成品は L2 の成果物（`CLAUDE.md`・業務フロー）を**静止**で見せる（L3 は試作中で揺れる／ライブデモは失敗すると逆効果。ライブは Add-on）。

| 節 | 伝えること | 核 | ねらい |
| --- | --- | --- | --- |
| 1. この講座の目標 | (1) 出回っている機能の "一端" を、まず体験する (2) CC を通して、自分の「動く環境・ルール・業務フロー」を作る。手元に残る成果物＝`CLAUDE.md`（自分のルール）／`業務フロー.md`（仕事の手順） | 目標＝一端を体験＋自分の環境を CC で作る | 行き先（完成品）を具体物で着地させる |
| 2. そこまでの道のり | 動く（環境を作る・L1）→ 育てる（自分用に・L2）→ つかう（自分の仕事で・L3） | 道のり＝動く→育てる→つかう | 全体像を渡し、動く（L1）から始まる必然を受け入れやすくする |
| 3. まず、動く環境をつくる | CC を動かすには、まず動く環境が要る。必要なのは3つ＝契約・インストール・認証。携帯でいうと 契約＝サービス契約（サブスク）／インストール＝端末を手に入れる／認証＝端末と契約の紐付け。流れは 契約 → インストール → 認証、まず契約から | 動く環境の地図＝3要素と流れ → まず契約 | 全体像を先に渡し、各 Unit では概要を繰り返さず詳細だけにする。締めは『動かすにはまず動く環境が要る、飛ばせない』＝不可避性で閉じ（売り込みの『だから始めよう』にしない）、次章（契約）へ橋渡しする |

## 確定事実・裏取り（出典）

- **公式の肩書きは "agentic coding tool / system"**。節3「本来はコーディング用」の出自はここが裏付け。
- **公式は非エンジニア／業務利用を後押し**（"作業の代行者""仕事へ広がる" は裏付けあり）。ただしその文脈は「非エンジニアもソフト／ツールを作れる」が主で、「事務作業の代行」とは少しズレる。だから節5 は "一気に広がっている" と断定せず "広がりを見せている" に留める。
- **「ファイル操作が本質」は公式語でなく研修側の解釈**（公式は「コーディングを自律完遂」、ファイル操作は手段）。節4 を "仕組み（描写）" に留めた根拠。
