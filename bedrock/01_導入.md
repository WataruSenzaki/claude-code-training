# 導入（ユニット）

> 用語スタック（各語は1階層だけを指す＝一意）:
> - **Bedrock** … L1（動く）の層
> - **ユニット** … 層の中身。標準で教えるユニットは番号付き。本ファイルはユニット「導入」
> - **Mainline / Add-on** … ユニットの中。Mainline＝外せない一本／Add-on＝標準外のおまけ（`add_on/` に置く）
> 対象が変わっても Mainline は不変・Add-on の選択だけが変わる（変更ダメージの局所化）。選ぶ行為＝構成。
> このユニットは L1 の最初。手を動かさない動機パートで、次の [02_契約.md](./02_契約.md) → [03_セットアップ.md](./03_セットアップ.md) へつなぐ。

## サマリ

- 結論: 導入の Mainline を「**チャットAIとの3差分 → 完成品を見せる → だから始めよう**」の動機の一本道に確定。手を動かさないユニットのため、**出口ゲート（二値の到達点）は置かない**（理由は章3）。
- 件数: Mainline 3節／Add-on 5本／フィルタで除外2件。
- 裏取り: チャットAIとの差分（複数ファイル横断・スキル・メモリがローカルに残る）は CC の設計思想に基づく。完成品は L2（確定済み）の成果物（`CLAUDE.md`・`業務フロー.md`）を静止画で先見せ（動く姿は見せない）。
- 次のアクション: 動機が立ったら [02_契約.md](./02_契約.md)（有料プランの手配）へ。実際に手を動かすのは [03_セットアップ.md](./03_セットアップ.md) から。

## 1. Mainline（動機の一本道・3節）

> 出口ゲートは置かない（章3参照）。代わりに「受講者が次（契約・セットアップ）に進む気になっている」が成立の目安。

| 節 | 伝えること | 核 | ねらい |
|---|---|---|---|
| 1. チャットAIとの違い＝3差分 | (1) 複数ファイルを横断して読む・直す (2) 手順を覚えさせて再利用できる（スキル）(3) 自分ルールがローカルに残り次回も効く（メモリ） | 「手を動かしてくれる・貯まる」 | 既知のチャットAIとの差で価値を腹落ちさせる |
| 2. 完成品を見せる | その差分の結果できあがる物を見せる。L2（確定済み）の成果物＝コマンド1つで `CLAUDE.md`（自分ルール）と `業務フロー.md`（自分の仕事の手順）がファイルになって残る。**動く姿は見せず、できあがった物（静止）だけ** | ゴール＝残る成果物を見せる | 抵抗感より先に「手元に何が残るか」を見せて引っぱる |
| 3. だから始めよう | 差分があり、成果物が残る。だから次に進もう、と契約→セットアップへ橋渡し | 動機を行動につなぐ | 次ユニット（契約→セットアップ）へ橋渡し |

### 確定事実（差分の中身）

- **複数ファイル横断**: チャットは貼り付けた範囲しか見ないが、CC はフォルダ内のファイルをパスで読み・直し・保存できる
- **スキル**: 繰り返す依頼を「手順」として登録し再利用できる（L2 Bridge で体験）
- **メモリ（CLAUDE.md）**: 自分ルールがローカルファイルに残り、次回起動でも効く（チャットの「毎回説明し直す」が消える）

### 前提条件（Mainline ではない）

- なし。導入は L1 の起点。受講者は「Claude Code を聞いたことがある／ない」のどちらでもよい

## 2. Add-on カタログ（目的タグ＋接続点）

> 目的タグは選別フィルタも兼ねる。「動機を強化するか／疑問を解消するか」のどちらでもない候補は、Add-on に入れない。
> 対象が変わったら、Mainline と Add-on の池はそのまま、構成で「どの Add-on を選ぶか」だけ変える。

| Add-on | 目的タグ | 接続点 |
|---|---|---|
| 完成品のライブデモ（成果物が「できあがる過程」を実演。L2 スキル or L3 のどれか。L3 は確定後） | 動機強化 | 節2 |
| 触る面の違い（ブラウザ／デスクトップアプリ／CLI で何ができるか。同一エンジンで成果は共通） | 疑問解消＋動機 | 節3 |
| 「ターミナル／黒い画面って何？怖い」への先回り | 疑問解消 | 節3前 |
| ローカルで完結する＝自分の PC の中で動く（漏洩不安の先回り） | 疑問解消（漏洩不安）＋動機 | 節1 or 節3 |
| 料金の全体像（次ユニットの予告。無料不可・有料が要る） | 疑問解消 | 節3後（02 への橋渡し） |

### フィルタで弾いたもの（動機でも疑問でもない＝Add-on に入れない）

- インストール手順・コマンド → [03_セットアップ.md](./03_セットアップ.md) の領域
- 具体的な操作（読ませる・直す）→ [04_基本操作.md](./04_基本操作.md) の領域

## 3. フラグ（非エンジニア向けで効く論点）

- **出口ゲートを置かない理由**: 導入は手を動かさない動機パートで、到達点を二値（できた／できない）で測れない。03/04 のような「打てば応答する」ゲートを無理に当てはめると、動機づけが手続きにすり替わって逆効果。成立の目安は「次（契約・セットアップ）に進む気になっている」という主観で十分とした。
- **差分→完成品の順にした理由**: 先に「何が違うか（差分）」で枠を作り、次に「その結果こうなる（完成品）」を見せると、差分→成果物→中身、で自然につながる。完成品を先に置くと差分の説明が後出しの繰り返しになる（節1で見せた物を節2で言い直す形）。
- **完成品を L2（確定済み）に依存させた理由**: L3（自社業務）は試作中で未確定。未確定の下流に依存すると、L3 が動くたび導入も揺れる。L2 の「スキルで業務フローをファイルに出す」核は固定で動かないので、先見せの素材として安定する。L3 はこの上に add-on を足すだけ。
- **動く姿を見せず完成品（静止）だけにした理由**: ライブデモは時間と環境に左右され、失敗すると逆効果。導入は動機パートなので「残る物（成果物）」を見せれば足り、動かす体験は L2 以降に任せる。
- **節3を「だからCLI」でなく橋渡しにした理由**: 3差分は CLI 固有でなくデスクトップアプリでも成立する（同一エンジン）。「差分があるからCLI」は論理が通らない。CLI/デスクトップ/ブラウザの違いは Add-on に逃がし、節3は「だから始めよう（契約→セットアップ）」の橋渡しに徹する。
- **3差分に絞った理由**: チャットAIとの違いは無数に挙げられるが、非エンジニアに刺さるのは「手を動かしてくれる（複数ファイル）」「貯まる（スキル・メモリ）」の2系統。多すぎる差分列挙は腹落ちを薄める。
