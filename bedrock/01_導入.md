## サマリ

- 結論: 導入で話す内容を「**CC とは＝ローカルファイルを読み書きできる道具（読む→自社文脈を覚える／書く→操作を代行）→ 使うとこうなる（完成品イメージ）→ この研修が行き先まで連れて行く（全体地図＋現在地）→ 使うにはまず土台が要る（→契約）**」の4節に確定。

## 構成（Mainline・4節）

> 出口ゲートは置かない（理由は「なぜこの構成か」）。手を動かさない動機＋理解パートで、到達を二値で測らない。成立の目安＝「『CC がどういう道具か』と『この研修がどこへ連れて行くか』が腹落ちし、次（契約）に進む気になっている」。
> 触る面: なし（手を動かすのは 03 から）。対象（誰が受けるか）で変わるのは完成品の例・刺し方だけ＝ Add-on（[add_on/00_index.md](./add_on/00_index.md)）。流れ自体は対象で変わらない。

| 節 | 伝えること | 核 | ねらい |
|---|---|---|---|
| 1. CC とは＝ローカルファイルを読み書きする道具 | 最近 Claude Code が広まっている。チャットとの決定的な違いは1点＝**自分の PC のローカルファイルを読み書きできる**（チャットは言うだけ・コピペや実行は人間）。だから (読む→)**自社文脈・自分ルールを覚えてくれる**／(書く→)**ファイル操作を代行してくれる** | 違いは1点（ローカルファイル操作）。覚える・代行はそこから来る利点＝理解 | 唯一の差で「CC とは何か」を腹落ちさせ、覚える・代行で"自分に効く"を予感させる |
| 2. 使うとこうなる＝完成品イメージ | その読み書きの結果できあがる物を見せる。L2 の成果物＝コマンド1つで `CLAUDE.md`（自分ルール＝覚えるの実物）と `業務フロー.md`（自分の仕事の手順＝代行で作られた実物）がファイルになって残る。**動く姿は見せず、できあがった物（静止）だけ** | 行き先＝残る成果物を見せる | 抽象でなく「手元に何が残るか」で到達像を与える |
| 3. 本講義の役割＝行き先まで連れて行く | この研修がさっきの完成品（行き先）まで連れて行く。道のりは「**動く（土台）→ 自分用に育てる（橋渡し）→ 自分の仕事に当てる（自社業務）**」の3段。今いるのは入口で、まだ手は動かさない | 現在地＋道のり＝研修の役割 | 全体像を持たせ、土台から始まる必然を受け入れやすくする |
| 4. 使うにはまず土台が要る → 契約へ | その道のりの第一歩＝土台（契約→セットアップ）。飛ばせない。だから次は契約から | 不可避性＝理解→手配の継ぎ目 | 次 Unit（契約→セットアップ）へ橋渡し |

前提条件: なし。導入は L1 の起点。受講者は「Claude Code を聞いたことがある／ない」のどちらでもよい。

## なぜこの構成か

- **「流行ってる→なぜ」から入る理由**: いきなり「CC とは」と定義すると説明書きになる。「最近広まっている → なぜか」で関心を入口にすると、その答え（＝ローカルファイルを読み書きする道具だから）が自然に「CC とは何か」の理解になる。動機を焚きつけるのでなく、既にある関心に CC の正体を接続する。
- **差分を1点に絞った理由（3差分をやめた）**: 旧版は「複数ファイル横断／スキル／メモリ」の3つを差分として並べたが、(a) "貯まる・覚える"はチャット系 AI もメモリ機能で追いつき差分でない、(b) CC の"覚える"はローカルファイル（`CLAUDE.md`）を読んでいるだけ＝違いは結局「ローカルファイルの読み書き」1点。よって差分は1点に絞り、覚える・代行は「読み書きできるからこうなる」利点として置く（読む→覚える／書く→代行 と1対1で対応）。だから"覚える"は「チャットにない凄さ」として売らない。
- **本講義の役割（全体地図＋現在地）を入れた理由**: 研修の入口を別 Layer（一度作った Compass）に切り出さず導入に一本化したので、「研修がどこへ連れて行くか」も導入が担う。完成品（行き先）を見せた直後に道のりと現在地を置くと、「土台から始まる」必然が腹落ちする（地図なしで土台に入ると "なぜ今これを" が迷子になる）。スコープの線引き（やる／やらない）は対象で変わりうるので Add-on 側に置く。
- **出口ゲートを置かない理由**: 導入は手を動かさない動機＋理解パートで、到達点を二値（できた／できない）で測れない。03/04 のような「打てば応答する」ゲートを無理に当てると、動機づけ・理解が手続きにすり替わって逆効果。成立の目安は「次（契約）に進む気になっている」で十分とした。
- **節4を「だから始めよう」でなく「使うには土台が要る→契約」にした理由**: 「すごい→だから始めよう」は売り込みの因果で、動機を持つ受講者には効かない。成立する因果は不可避性＝「使うにはまず土台（契約→セットアップ）が要る、飛ばせない」。これなら理解→手配の継ぎ目として論理が閉じ、次章（契約）に具体的につながる。
- **完成品を L2（確定済み）に依存させた理由**: L3（自社業務）は試作中で未確定。未確定の下流に依存すると、L3 が動くたび導入も揺れる。L2 の「スキルで業務フローをファイルに出す」核は固定なので、先見せの素材として安定する。
- **動く姿を見せず完成品（静止）だけにした理由**: ライブデモは時間と環境に左右され、失敗すると逆効果。導入は動機＋理解パートなので「残る物（成果物）」を見せれば足り、動かす体験は L2 以降に任せる（ライブは Add-on）。
- **触る面（CLI/デスクトップ/ブラウザ）を Add-on に逃がした理由**: ローカルファイル操作は CLI 固有でなくデスクトップアプリでも成立する（同一エンジン）。「違いがあるから CLI」は論理が通らない。触る面の違いは Add-on にし、構成は「CC とは何か→完成品→本講義の役割→契約へ」に徹する。
