## 1. 何をやるか（Mainline・5段）

> 出口ゲート: **「自分のPCで何か打ち込んだら Claude Code が応答して返ってくる」**（二値・対象非依存・イベント非依存）
> 触る面: CLI（ターミナル）固定。唯一のパラメータ = OS（段1のインストールと段2のPATHでコマンドが分岐する）

| 段 | やること | Mac | Windows |
|---|---|---|---|
| 1. インストール | 端末を開いて1行貼る | ターミナル（Terminal.app）で `curl -fsSL https://claude.ai/install.sh \| bash` | PowerShell で `irm https://claude.ai/install.ps1 \| iex` |
| 2. パスを通す | 端末を開き直して `claude --version` が返るか確認。返らなければ PATH を通す（手順は確定事実） | 反映先 `~/.local/bin` | 反映先 `%USERPROFILE%\.local\bin` |
| 3. 起動 | `claude` と打つ | `claude` | `claude` |
| 4. ログイン（＝認証） | 初回起動で自動的に促される → ブラウザでサイン → 端末に戻る | 同左 | 同左 |
| 5. 応答確認【ゲート】 | 何か打つ（例「こんにちは、何ができますか？」）→ 応答が返れば完了 | 同左 | 同左 |

## 2. なぜこの構成か

- **「どこで動かすか」を Mainline から外した理由**: 公式 quickstart は「コードプロジェクトを開いて `cd` してから `claude`」を前提にするが、非エンジニアの業務ユーザーに"プロジェクト"はない。出口ゲート（打てば応答する）はフォルダに依存しないので、「どこで動かすか」は Mainline から外し Add-on（段5後）に置いた。
- **パスを通すを Mainline に入れた理由**: 公式上はインストーラが PATH を設定し「端末を開き直せば反映される」前提。だが過去の研修で**全員が install 直後に `claude` を見つけられず起動できなかった**（発生率100%）。回避不能の頻度なので、開き直し＋PATH 通しを本筋の段（段2）として明示した（公式では troubleshooting 扱いだが現場頻度を優先）。

## 確定事実（裏取り済み）

- **Node.js 不要・Git 任意**（ネイティブインストーラ。Git 未導入でも Windows は PowerShell で動く）
- インストール後は**バックグラウンド自動更新**（当日アップデート操作は不要）
- インストール確認は `claude --version`、詳細診断は `claude doctor`（Mainline には載せず Add-on に置く）
- **インストール先**: Mac/Linux `~/.local/bin/claude` ／ Windows `%USERPROFILE%\.local\bin\claude.exe`。ここが PATH に無いと `claude` は command not found
- **PATH の通し方**（出典: troubleshoot-install）: 多くは**端末を開き直すだけ**で反映（インストーラが設定済みのため）。反映されなければ手動追加 — Mac/Linux は `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc`（bash は `~/.bashrc`）→ `source`、Windows(PowerShell) は `$p=[Environment]::GetEnvironmentVariable('PATH','User'); [Environment]::SetEnvironmentVariable('PATH',"$p;$env:USERPROFILE\.local\bin",'User')` → 新しい端末を開く
