# セットアップ（ユニット）

> 用語スタック（各語は1階層だけを指す＝一意）:
> - **Bedrock** … L1（動く）の層
> - **ユニット** … 層の中身。標準で教えるユニットは番号付き。本ファイルはユニット「セットアップ」
> - **Mainline / Add-on** … ユニットの中。Mainline＝外せない一本／Add-on＝標準外のおまけ（`add_on/` に置く）
> 対象が変わっても Mainline は不変・Add-on の選択だけが変わる（変更ダメージの局所化）。選ぶ行為＝構成。

## サマリ

- 結論: セットアップの Mainline を「自分のPCで打てば Claude Code が応答する」到達までの最小4段に確定。触る面は CLI 固定、唯一のパラメータは OS（Win/Mac）。
- 件数: Mainline 4段／Add-on 12本／フィルタで除外2件。
- 裏取り: インストール・認証手順は公式ドキュメントで確認済（Node.js 不要・Git 任意）。出典は末尾。
- 次のアクション: この確定版を土台に、他ユニット（基本操作など）も同じ Mainline＋Add-on で棚卸しする。

---

## 1. Mainline（最小4段）

> 出口ゲート: **「自分のPCで何か打ち込んだら Claude Code が応答して返ってくる」**（二値・対象非依存・イベント非依存）
> 触る面: CLI（ターミナル）固定。唯一のパラメータ = OS（段1のコマンドだけ分岐する）

| 段 | やること | Mac | Windows |
|---|---|---|---|
| 1. インストール | 端末を開いて1行貼る | ターミナル（Terminal.app）で `curl -fsSL https://claude.ai/install.sh \| bash` | PowerShell で `irm https://claude.ai/install.ps1 \| iex` |
| 2. 起動 | `claude` と打つ | `claude` | `claude` |
| 3. ログイン | 初回起動で自動的に促される → ブラウザでサイン → 端末に戻る | 同左 | 同左 |
| 4. 応答確認【ゲート】 | 何か打つ（例「こんにちは、何ができますか？」）→ 応答が返れば完了 | 同左 | 同左 |

### 確定事実（churn の震源だった点）

- **Node.js 不要・Git 任意**（ネイティブインストーラ。Git 未導入でも Windows は PowerShell で動く）
- インストール後は**バックグラウンド自動更新**（当日アップデート操作は不要）
- インストール確認は `claude --version`、詳細診断は `claude doctor`（Mainline には載せず、Add-on に置く）

### 前提条件（Mainline ではない）

- Claude の Pro / Max / Team / Enterprise 契約。**無料プランは Claude Code 非対応**
- サブスク契約の手配は「前提条件」であって Mainline の工程ではない

## 2. Add-on カタログ（目的タグ＋接続点）

> 目的タグは選別フィルタも兼ねる。「動機を強化するか／疑問を解消するか」のどちらでもない候補は、Add-on に入れない。
> 対象が変わったら、Mainline と Add-on の池はそのまま、構成で「どの Add-on を選ぶか」だけ変える。

| Add-on | 目的タグ | 接続点 |
|---|---|---|
| なぜチャットAIでなく CC か（複数ファイル／スキル／メモリの3差分） | 動機強化 | 段1前 |
| 完成イメージのデモ（「終わりにこれができる」を見せる） | 動機強化 | 段1前 |
| ローカルで完結する（自分の PC の中で動く） | 動機強化＋疑問解消（漏洩不安） | 段1前 or 段4後 |
| 「ターミナルって何？黒い画面が怖い」 | 疑問解消 | 段1前 |
| PowerShell と CMD の見分け（`PS C:\` か `C:\` か） | 疑問解消 | 段1（Win 限定） |
| Node.js／Git は要るのか | 疑問解消 | 段1 |
| インストールできたか確認（`claude --version` / `claude doctor`） | 疑問解消 | 段1後 |
| 無料プランで使える？（不可・要契約） | 疑問解消 | 段3 |
| ブラウザ認証が開かない／通らない時 | 疑問解消（トラブル） | 段3 |
| データは安全か／入力は学習に使われるか | 疑問解消 | 段3後（守秘義務が重い対象で選択） |
| 他の触り方（デスクトップ／ブラウザ／IDE。同一エンジンで成果は共通） | 疑問解消＋動機 | 段4後 |
| どのフォルダで動かすか（CC が見ている場所） | 疑問解消 | 段4後 |

### フィルタで弾いたもの（動機でも疑問でもない＝Add-on に入れない）

- モデル指定 → 運用都合（構成の話）
- サブスク契約の手配 → 前提条件

---

## 3. フラグ（非エンジニア向けで効く論点）

公式 quickstart は「コードプロジェクトを開いて `cd` してから `claude`」を前提にしている。非エンジニアの業務ユーザーには"プロジェクト"がない。ただし**出口ゲート（打てば応答する）はフォルダに依存しない**ため、「どこで動かすか」は Mainline から外し、Add-on（段4後）に置いた。Mainline を汚さずに済む。
