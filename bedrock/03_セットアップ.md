## 1. 何をやるか（Mainline・5段）

> 出口ゲート: **「自分のPCで何か打ち込んだら Claude Code が応答して返ってくる」**（二値・対象非依存・イベント非依存）
> 触る面: CLI（ターミナル）固定。唯一のパラメータ = OS（段1のインストールと段2のPATHでコマンドが分岐する）。起動・利用を GUI（デスクトップアプリ）にする案も出たが、GUI 化は別 distribution＝install も起動も GUI 側に移る別ルート（CLI で入れて GUI 起動という中間は未確認）。今回は **all-CLI 前提**で進める（GUI 化は Add-on「他の触り方」に保留・2026-06-05）。
> 段2「パスを通す」を本筋に入れる理由: 過去の研修で install 直後に全員が `claude` を見つけられず起動できなかった（発生率100%）。公式は troubleshooting 扱いだが、回避不能の頻度なので本筋の段にする。
> スコープ: 「どこで動かすか」（起動フォルダ＝基地・今回はデスクトップ）は **04 基本操作の本筋へ**移した（非エンジニアのつまずき先回り＋L2 CLAUDE.md の伏線）。03 の起動・応答確認はフォルダに依存しない。"縛られない／パス自由" と CLAUDE.md＝起動場所基準 の深掘りは Add-on のまま。

## 確定事実（裏取り済み）

- **Node.js 不要・Git 任意**（ネイティブインストーラ。Git 未導入でも Windows は PowerShell で動く）
- インストール後は**バックグラウンド自動更新**（当日アップデート操作は不要）
- インストール確認は `claude --version`、詳細診断は `claude doctor`（Mainline には載せず Add-on に置く）
- **インストール先**: Mac/Linux `~/.local/bin/claude` ／ Windows `%USERPROFILE%\.local\bin\claude.exe`。ここが PATH に無いと `claude` は command not found
- **PATH の通し方**（出典: troubleshoot-install）: 多くは**端末を開き直すだけ**で反映（インストーラが設定済みのため）。反映されなければ手動追加 — Mac/Linux は `echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc`（bash は `~/.bashrc`）→ `source`、Windows(PowerShell) は `$p=[Environment]::GetEnvironmentVariable('PATH','User'); [Environment]::SetEnvironmentVariable('PATH',"$p;$env:USERPROFILE\.local\bin",'User')` → 新しい端末を開く
