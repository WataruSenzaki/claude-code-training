# Claude Code 研修教材（再考）— 目的とコンセプト

> 何を作っているかの忘れ防止メモ＆全体像。L1・L2 の中身は本ファイル（下記「各 Layer の中身」）。L3 は [instances/](./instances/) で別管理。
> **なぜこの形か（設計の根拠）は [DESIGN.md](./DESIGN.md)。作り手との進め方は [CLAUDE.md](./CLAUDE.md)。**

## 大目的

何回やっても同じ結果になる、**再利用可能な研修教材の骨格**を作る。

- 対象: 非エンジニアの業務効率化希望者（特定イベント・特定受講者に依存しない汎用）
- 範囲: Claude Code の**インストール → 自社業務に使える**まで
- 背景: 過去に作って失敗した。場当たりでなく、エンジニア的に再現性・再利用性を持たせたい

## 設計の狙い

ターゲットが変わったときの**「変更ダメージ」を局所化**する。普遍の部分（L1・L2）と、対象ごとに差し替える部分（L3）を構造で分離する。

## 用語（各語は1つの意味だけを指す＝一意）

> 定義はここが正本。各 Unit ファイルはここを参照し、定義を複製しない。

- **Layer** … capability の段。L1 Bedrock（動く）／ L2 Bridge（橋渡し）／ L3 Instance（自社業務）
- **Unit** … Layer の中身。標準で教える Unit は番号付き（例: 01_導入〜04_基本操作）
- **Mainline** … Unit の「話す内容の幹」。外せない一本。対象が変わっても不変
- **Add-on** … 標準外のおまけ。対象（受講者）で「どれを足すか」だけが変わる。各 Layer の `add_on/` に集約
- **Template / Instance** … Template＝対象に依存しない共通部分（L1・L2）／ Instance＝対象ごとに差し替える中身（L3）。L3 の Layer 名 "Instance" はこの Instance のこと
- **狙い** … Mainline（不変）と Add-on（可変）を分け、対象が変わったときの変更ダメージを局所化する

## Layer 構成（L1 / L2 / L3）

> capability は「動く→橋渡し→自社業務」と上がる階段（L1〜L3）。研修の入口（流行る理由＝CCとは／完成品／なぜやるか）は別 Layer に切り出さず、L1 Bedrock の最初の Unit「導入」に統合する（対象で変わるのは完成品の例＝Add-on レベルで、流れ自体は不変だから）。

| Layer | 役割／ゴール | 中身 | 所属テスト |
|---|---|---|---|
| **L1 Bedrock** | 動く（install→PCで動かせる） | 導入／契約／セットアップ／基本操作 | 外したら"動く"に到達できないか |
| **L2 Bridge** | L1→L3 の橋渡し | CCのすごさを[説明＋体験]で持つプール（CLAUDE.md/Skills/MCP…） | 体験して"自分の仕事に使えそう"が生まれるか |
| **L3 Instance** | 自社業務につながる | タイプごとの Instance＝1目次（ハンズオン/振り返り/データ安全/例）。Template（L1・L2）に対する Instance | Layer が選ぶ側。変更はここに閉じる |

- 研修の入口（導入）は L1 Bedrock の最初の Unit。**動機を作る場ではなく**、既にある動機（自分で楽にしたい）に「**CC とは何か**（作業の代行者→チャットとの違い→本来はコーディング用→仕組みはファイルの読み書き→仕事へ広がる）→ **本講義の役割**（行き先＝完成品 → 道のり → まず動く環境をつくる）」を接続する。対象で変わるのは完成品の例・刺し方＝Add-on で、流れ自体は不変
- L2 は**順序なしのプール**、L3 が「このタイプにはどれを入れるか」を選ぶ。1タイプ＝1目次
- 各 Unit の中は **Mainline（外せない一本）＋ Add-on（肉付け）**。標準で教える Unit は番号付き、標準外の Add-on は各 Layer の `add_on/` へ
- 呼称: 旧「モジュール／Base Module／Option Module」は廃止。**Bedrock は L1 を指す**。Option（データの安全等）は L3 の対象選択に吸収

## 各 Layer の中身（L1・L2）

> L3 は対象タイプごとに L1＋L2 を選んで組む Layer（Template（L1・L2）に対する Instance）。独立フォルダで別管理 → [instances/](./instances/)。

### L1 Bedrock（動く）
順序あり（導入→契約→セットアップ→基本操作）。各 Unit は Mainline＋Add-on。標準は番号付き、標準外は `bedrock/add_on/`（必要時に作成）。**スライドは L1 全体を1デッキ [`slides/Bedrock.html`](./slides/Bedrock.html)（4章＝導入/契約/セットアップ/基本操作）に統合**（導入が共通の型）。

| # | Unit | ねらい | 状態 |
|---|---|---|---|
| 1 | [導入](./bedrock/01_導入.md) | 章1 CC とは（作業の代行者→チャットとの違い→本来はコーディング用→仕組みはファイルの読み書き→仕事へ広がる）／章2 本講義の役割（行き先→道のり→まず動く環境をつくる） | 確定（骨子・2章立て。スライドは Bedrock.html 章1） |
| 2 | [契約](./bedrock/02_契約.md) | Claude アカウント＋有料プラン（サブスク経路。API は add_on） | 確定（中身も） |
| 3 | [セットアップ](./bedrock/03_セットアップ.md) | install→応答（ゲート） | 確定（中身も） |
| 4 | [基本操作](./bedrock/04_基本操作.md) | 話しかけ→読ませ／直し→承認 ＋ 詰まっても自力復帰（自立） | 確定（中身も） |

### L2 Bridge（橋渡し）
順序なしのプール（番号＝汎用標準で教える順。L3 が選んで組み替えられる）。全体の通しは [bridge/00_index.md](./bridge/00_index.md)。標準外は [bridge/add_on/](./bridge/add_on/)。
共通の軸＝**「自分のものをCCに貯めて育てる」**（情報＝CLAUDE.md／手順＝Skills。ローカルに残り次回も効くのがチャットとの差）。

| # | Unit | 体験の核 | 状態 |
|---|---|---|---|
| 1 | [CLAUDE.mdとは](./bridge/01_CLAUDE.mdとは.md) | 公式の解説＋素手で1行書く→再起動→AIの振る舞いが変わる（記憶） | 確定（概念＋素手版） |
| 2 | [スキルとは](./bridge/02_スキルとは.md) | 動かす前に「呼び出せる手順」を一言で渡す（地図） | 構成確定（中身は確認待ち） |
| 3 | [配布スキルを動かす](./bridge/03_配布スキルを動かす.md) | 1コマンド→自分・自社・業務フローを聞かれ答える→自分用フォルダができる | 構成確定（出力の形は要確認） |
| 4 | [こんなことできる→L3](./bridge/04_種明かしとL3予告.md) | 種明かし（素手の自動版／2スキル連携／配れる）→L3予告 | 構成確定（中身は確認待ち） |
| add_on | [MCP](./bridge/add_on/mcp.md) | 外部サービスとつなぐ | 保留（標準外） |

- **非エンジニア汎用の通し（標準の順 1→4）**: 1. CLAUDE.mdとは（公式解説＋素手で1行・記憶）→ 2. スキルとは（動かす前の一言）→ 3. 配布スキル起動（自分・自社・業務フローを聞かれ答える→自分用フォルダ）→ 4. 種明かし（素手の自動版・2スキル連携・配れる）＋L3予告（業務フローを材料に自社用スキル）
- **L2 の未定**: スキル本体の実装/改修（`/profile`→聞く役・`/scan`→業務フロー役、尺10〜15分への圧縮）／出力の形（自社を独立ファイルにするか・業務フローを図まで出すか）／プールの拡充
